数据契约：一个数值至少带两种时间

OPC UA DataValue包含值、状态码、源时间和服务器时间。源时间与服务器时间不能互换；客户端至少检查状态码严重程度。工程单位则属于相关变量元数据，不能假定数值本身已经携带单位。这是标准依据，不是新发布的矿山生产案例。

评测方向：先阻止“偷看未来”，再谈模型能力

scikit-learn官方文档把预测时不可用的信息进入训练定义为数据泄漏，并要求先拆分数据，再只在训练集拟合预处理。对矿山维修智能体，同样要冻结当时可检索的手册和工单版本；晚到数据、事后维修结论不能穿越回预测时刻。此处是将通用方法迁移到矿业的教学建议，不是已验证的现场收益。

案例深读

历史研发案例：AI4I 2020，不是矿山生产实绩

UCI于2020-08-29接收的AI4I数据集含10,000条合成记录，提供六个输入特征及故障相关标签。问题是如何在真实维修数据难公开的条件下研究分类与预测维护。输入包括产品类型、空气／过程温度、转速、扭矩和工具磨损；温度单位为K。它不是浆液泵实测数据，Product ID也不能直接当成矿山设备台账编号。

UCI · AI4I 2020（2020-08-29捐赠，CC BY 4.0）

方法与已证实内容

数据说明给出了温度随机游走、转速／扭矩生成方式及磨损、散热、功率、过应力、随机故障等合成机制。能够核验的是数据规模、变量和生成规则；本期未训练模型，也没有可报告的准确率或停机收益。Machine failure及TWF/HDF/PWF/OSF/RNF均应作为标签信息审查，不能把故障子标签当输入去预测总故障标签。

局限：识别同一行故障，不等于提前预警

公开字段没有足够的现场采集时间、数据可用时间与真实资产生命周期信息，不能只凭UID顺序就声称验证了“未来24小时故障预警”。按合成规律获得高分，也不证明对真实矿山工况、传感器漂移或未见故障有效。该案例属于公开合成研发材料；不属于矿山试点或生产部署，也不是厂商收益宣传的独立验证。

PART 03

自动化知识

概念1｜数据契约：身份、时间、量纲、质量

设备身份使用厂区／系统命名空间下的稳定assetId，并维护传感器tag与设备映射的生效时间。至少记录sourceTime、平台首次可用的availableTime、数值、单位、原始质量码、采样／变化上报方式和schemaVersion。服务器时间不一定等于分析平台可用时间，需单独采集。存储统一UTC，展示可转圭亚那UTC−4。300 K = 26.85 °C；温差换算则不能再减273.15。Good不等于已证明传感器正确，仍需校准与合理性检查。

OPC Foundation · DataValue（规范，2026-10-14查阅） · OPC Foundation · AnalogItem与工程单位（规范，2026-10-14查阅）

概念2｜数据连接不改变控制责任

PLC负责确定性的设备控制，DCS负责过程控制体系，SCADA承担监视与操作界面。历史库／经批准的只读接口把数据交给分析层。规则做字段校验和质量分流，ML做经过离线验证的评分，生成式助手解释证据并写草稿，智能体只在授权工具范围内查询补证。Uncertain应单独分流，Bad不用于诊断；不能把缺测填0当正常。源时间很旧可能只是变化上报的值未变，判定“陈旧”需结合服务器更新时间、心跳和采集模式，不能机械地只看sourceTime。

概念3｜按决策时刻冻结评测

设预测时刻t与未来观察窗H。输入必须同时满足sourceTime≤t和availableTime≤t；标签描述(t,t+H]是否发生目标故障，只有观察窗完整且维修结论已确认后才能评分。窗口尚未结束或记录不完整的样本标为待定，不当成负例。先按时间划分开发／验证／最终测试；同一故障事件的重叠窗口不得跨集合，边界需留出与特征窗、标签窗相匹配的隔离区。跨设备泛化另做留出设备评测。TimeSeriesSplit不会自动处理事件组、标签延迟或真实时长隔离，gap按样本数计，不能直接等同小时。

应用方案

教学方案｜浆液泵维修证据包v2

承接上期工单草稿：新增设备映射、温度／振动／负荷单位、质量码、双时间戳、传感器校准记录和手册版本。先离线导入经批准的数据副本，再建立“决策时刻快照→规则校验→可选模型评分→证据引用→人工审核”的流程。输出显示有效样本、排除原因、缺失证据和不确定性；未知设备不得由模型猜测映射。这里是拟议方案，尚未在真实矿山试点。

权限与集成

实际试点需由现场批准历史库与CMMS的最小权限：分析账号只读，维修草稿先存隔离区；调度／维修负责人批准建单，控制工程师负责控制变更。工具白名单禁止PLC写入、启停、复位保护和修改报警值。引用记录保留事件ID、文档版本、可用时间、规则／模型版本；工具失败要明确报错，不编造返回值。本课只操作模拟数据，不连接任何生产控制系统。

数字孪生的适用条件

本期不为字段清洗建立复杂孪生。只有要推演泵／管路工况或维修窗口，并且拥有可校准的物理参数、边界条件、同期负荷、时间对齐数据及独立验证工况时，才考虑孪生。先定义误差和适用工况；超出范围拒绝推演。仪表盘不是自动具备预测能力的孪生，仿真输出也不是故障真值。

自动学习仍然受控

线上积累数据可供离线再训练，但每版要经数据审计、冻结测试、人工签核、版本发布与回滚演练。模型分数变化不授予系统自行修改生产逻辑的权限。

PART 05

动手练习

目标与准备｜25分钟，只用模拟数据

目标：识别“看起来合理但不能进入当时决策”的记录，生成两条标准化输入及六条带原因的排除记录，再完成一张防泄漏评测卡。使用已有Python 3本地解释器即可，无第三方包、账号、收费服务或联网需求；没有环境可手工在表格执行。代码仅是课堂最小示例，不是工业数据接入程序。

0—5分钟｜先做预测时刻判断

预测时刻设为2026-10-14 10:00圭亚那时间，即14:00 UTC。P01与P02是唯一有效模拟设备；温度允许K与degC，质量只接受Good。R6源时间虽早，但直到14:01才可用，不能回填到14:00的预测。质量分流是课堂约定，未设置任何现场报警阈值。

5—15分钟｜运行并解释八条模拟记录

# Python 3 标准库；只处理内存中的模拟数据，无网络、无文件写入。
from datetime import datetime
from collections import Counter

def ts(s):
    d = datetime.fromisoformat(s.replace("Z", "+00:00"))
    if d.tzinfo is None:
        raise ValueError("missing timezone")
    return d

cutoff = ts("2026-10-14T10:00:00-04:00")
# id, asset, sourceTime, availableTime, value, unit, quality
rows = [
 ("R1","P01","2026-10-14T13:59:00Z","2026-10-14T13:59:02Z",300,"K","Good"),
 ("R2","P02","2026-10-14T09:59:00-04:00","2026-10-14T09:59:02-04:00",26.85,"degC","Good"),
 ("R3","P99","2026-10-14T13:59:00Z","2026-10-14T13:59:02Z",300,"K","Good"),
 ("R4","P01","2026-10-14T13:59:00Z","2026-10-14T13:59:02Z",300,"K","Bad"),
 ("R5","P01","2026-10-14T13:59:00Z","2026-10-14T13:59:02Z",300,"K","Uncertain"),
 ("R6","P01","2026-10-14T13:59:00Z","2026-10-14T14:01:00Z",300,"K","Good"),
 ("R7","P01","2026-10-14T13:59:00","2026-10-14T13:59:02Z",300,"K","Good"),
 ("R8","P01","2026-10-14T13:59:00Z","2026-10-14T13:59:02Z",300,"unknown","Good"),
]
accepted, rejected = [], []
for rid, asset, source, available, value, unit, quality in rows:
    reason = None
    if asset not in {"P01", "P02"}: reason = "unknown_asset"
    elif quality != "Good": reason = "quality_" + quality
    elif unit not in {"K", "degC"}: reason = "unknown_unit"
    else:
        try:
            st, at = ts(source), ts(available)
            if st > at: reason = "clock_order"
            elif st > cutoff or at > cutoff: reason = "not_available_at_cutoff"
        except ValueError:
            reason = "invalid_time"
    if reason:
        rejected.append((rid, reason))
    else:
        c = round(value - 273.15 if unit == "K" else value, 2)
        accepted.append((rid, asset, c))
assert accepted == [("R1", "P01", 26.85), ("R2", "P02", 26.85)]
assert len(rejected) == 6
print("accepted:", accepted)
print("rejected:", rejected)
print("counts:", dict(Counter(reason for _, reason in rejected)))

15—25分钟｜建立不泄露答案的评测卡

  • 写下任务：在时刻t生成故障风险证据包；教学标签窗口H=24小时，不能把H当作现场已验证的预警提前量。
  • 模型输入白名单仅含当时可用的设备／工况／传感器特征；将repairConclusion、replacedPart、failureSubtype和工单关闭时间放入独立标签区，禁止智能体检索。
  • 将R6改成13:59:03可用后重跑：应有3条接受记录。再恢复原值，去掉R1的时区：应仅剩1条接受记录。修改代码中的assert预期并解释原因；不要删除校验来掩盖差异。
  • 用纸面样本A（t=10月1日10:00，H=24小时，标签10月2日12:00可用）与B（t=10月3日10:00，H=24小时，标签10月4日12:00可用）设计时间切分。若模型在10月3日09:00冻结，A可用于训练，B只能事后评分；未来B标签不能进入模型或检索库。
  • 补写同一故障episodeId不能跨集合的检查，以及“数据不足→暂不判断”的输出。两条纸面样本只验流程，不能给出可信模型性能。
展开练习参考答案

原始运行接受R1、R2，各26.85 °C；R3未知设备、R4 Bad、R5 Uncertain、R6决策时不可用、R7缺时区、R8未知单位，共6条排除。有效率2/8=25%，这是人为构造练习的结果，不是任何矿山的数据质量统计。R6提前可用后接受3条；恢复后再去掉R1时区则接受1条。A标签在冻结前已可用，B标签要到10月4日12:00后才能用来评分。测试集标签可供最终评测，但不能反馈到已冻结模型、提示词、检索索引或阈值选择中。

PART 06

结论与下期

本期验收

  • 能解释assetId与Product ID的区别、K与°C的换算、源时间与可用时间的区别。
  • 八条模拟数据的接受／排除结果可复现，Bad、Uncertain、未知单位和晚到数据都有明确去向。
  • 评测卡包含预测时刻、观察窗、标签可用时间、事件组隔离、冻结版本及拒答条件。
  • 真实试点分别记录输入有效率、事件级召回／精确率、每设备日误报、提前量、拒答率和人工核查时间，并注明分母与观察期；不只报告总体准确率。

待验证假设

统一身份与单位能否减少错误引用？按availableTime截断是否会降低离线分数却更贴近实用表现？增加质量拒答能否减少误工单，又是否漏掉真实异常？这些是待验证假设。本期只证明课堂规则可执行，没有证明生产收益、诊断能力或数字孪生精度。

下一课｜从干净记录到可追溯证据

推进设备手册版本、适用型号和证据引用：在冻结资料库中检索，遇到过期手册、型号冲突或无证据时拒答。比较固定检索工作流与受限智能体，并用同一份事件级评测集记录正确引用率及人工审核成本。

从可靠数据出发，用证据连接学习与应用。
